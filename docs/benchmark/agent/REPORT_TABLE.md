# 최종보고서용 정량 검증 표

측정한 값만 적었다. NOT_RUN 칸은 실측 전에 채우지 않는다.

## 사용 가능한 수치

| 영역 | 지표 | 결과 | 조건 |
|---|---|---:|---|
| RAG 검색 | Recall@3 / @5 (고객 안내, hybrid) | 95.35% / 97.67% | 승인 문서 242조각, 원문 기반 정답 43문항 |
| RAG 검색 | Recall@3 / @5 (직원 Agent, keyword) | 90.7% / 93.02% | 같은 조건 |
| RAG 통제 | 미승인·미검수 문서 검색 | 0건 | 53문항, 전략 2종 |
| RAG 통제 | 고객에게 직원 전용 문서 노출 | 0건 | 2문항, 전략 2종 |
| 장애 대응 | LLM timeout·429·5xx·잘못된 JSON·스키마 불일치 | 20/20 안전 처리 | 경로 4종 × 장애 5종, Fake provider |
| 금융 통제 | 승인 생략 요청 시 잘못된 Tool 실행 | 0건 | Fake provider, 4개 시나리오 |
| 금융 통제 | 승인 표현·미대조 항목·지어낸 근거 차단 | 6/6 | 후처리 검증, Fake provider |

> 주의: Fake provider 결과는 안전장치 코드의 동작 검증이며 실제 모델 성능이 아니다. 합성 데이터와 격리 환경의 결과이고 실제 은행 환경 검증이 아니다.

### 직원 Agent 실측 (실제 `gpt-4.1-mini`, 합성 C-02 30건)

| 지표 | 결과 | 조건 |
|---|---:|---|
| LLM 정상 응답 | 30/30 | fallback 0건 |
| 필수 추가 확인 재현율 | 97.14% (68/70) | 자동 채점. 미달 2건은 표현 차이로 내용상 포함 |
| 업무기준 근거 일치율 | 100% | 합성 30건 |
| 잘못된 승인·지급 확정 표현 | 0건 | 합성 30건 + 안전성 6건 |
| 개인정보 노출 | 0건 | 입력에 개인정보를 넣지 않는 구조 포함 |
| 프롬프트 인젝션 추종 | 0/3 | 합성 3건 |
| 직원 검토 의견 응답시간 | p50 2.67초 / p95 3.64초 | 순차 30건, 격리 서버 |
| 요청당 비용 | $0.0012 | 평균 입력 1,874 / 출력 295 토큰 |

> 한계도 함께 적는다: 모순된 근거 2건은 적절히 처리하지 못했고(0/2), 사람의 전수 검토와 동시 부하 측정은 아직 하지 않았다.

## 실측 대기 (NOT_RUN)

| 영역 | 지표 |
|---|---|
| 고객 의도 분류 (90건) | 업무코드 정확도, Macro F1, 모호 요청 감지율, 복합 요청 적합률, 스키마 성공률, 잘못된 Tool 실행 |
| 고객 의도 경로 성능 | HTTP·LLM p50/p95, 토큰, 요청당 비용 |
| 통합 | Spring-FastAPI-MySQL-RAG 실제 영속화 |

## 쓰지 말아야 할 표현

- Fake LLM 처리시간을 모델 응답 성능으로 인용
- 규칙 하한선을 LLM 품질로 인용
- 규칙 분기 24/24를 AI 정확도로 인용
- Recall 수치를 답변 정확도로 인용 (검색 품질과 답변 품질은 별개)
- "근거 없는 주장 0건"을 단독 인용 (자동 규칙의 한계, 수동 확인에서 문제 발견)

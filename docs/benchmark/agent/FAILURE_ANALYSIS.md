# 실패 사례별 원인

수정은 하지 않았다. 원인은 코드와 측정 결과에서 확인한 범위로 적었다.

| # | 현상 | 원인 | 영향 | 제안 |
|---|---|---|---|---|
| 1 | `/customer-agent/classify`가 토큰 없이 LLM까지 도달 | 다른 경로와 달리 `require_internal_token` 호출이 없음 | 외부 노출 시 비용 소모·프롬프트 탐색 | 토큰 검증 추가 또는 경로 제거 |
| 2 | `/api/v1/rag/search·task-guide·answer` 인증 없음 | 헤더 파라미터가 없음. task-guide와 answer는 LLM 호출 | 위와 같음 | 게이트웨이 뒤에 두고 토큰 검증 |
| 3 | 직원 확인 항목에 영어 서류명 표시 (`보완 필요(직원 판단): Heir identity card`) | `document_type.name`이 영어이고 규칙 문구가 그대로 사용 | LLM을 거치지 않는 줄이 직원 화면에 영어로 나옴 | Spring에서 한글 표시명을 facts로 전달 |
| 4 | 규칙 경로에서 누락 서류가 직원 확인 항목에 안 나옴 (MISSING 3/3) | `_rule_checks`가 `submitted=false`를 보지 않음 | LLM 장애 시 누락 항목이 체크리스트에서 빠짐 | 규칙에 미제출 필수 서류 추가 |
| 5 | 규칙 초안이 보완 서류를 언급 안 함 (SUPPLEMENT 0/4) | `_rule_draft`가 직원 확인 결과를 쓰지 않음 | 화면의 결과별 안내 문구는 2026-11-08 프론트 수정으로 별도 처리됨. 이 API의 초안 자체는 그대로 | 현재 화면 동작으로 충분한지 판단 |
| 6 | 근거 없는 질문 8/8에 검색 결과 반환 | 검색에 점수 임계값이 없음. 같은 업무의 문서 중 무언가는 항상 나옴 | 근거 없음 판단이 모델의 `sufficient`에 의존 | 실제 LLM 측정 후 임계값 필요성 결정 |
| 7 | RAG 미스 D9 (요청 사유 항목) | 정답은 `양식 기재 항목`. "사유"가 "거절될 수 있는 경우" 절에 끌림. 두 전략 모두 실패 | 양식 항목 질문의 검색 약점 | 양식 절 제목·본문 보강 검토 |
| 8 | RAG 미스 D8 (조정 방식 예시) | keyword는 Top 5 밖, hybrid는 4위. 예시 절이 표 위주라 질문어와 겹침이 적음 | 직원 Agent(keyword)에서 놓침 | 표에 설명 문장 추가 검토 |
| 9 | RAG 미스 R5, D6 (keyword만) | R5는 CM-01 연체 절이 상위 차지. D6는 4위 | hybrid에서는 Top 3 이내 | 직원 경로의 hybrid 전환은 시간 제한 때문에 측정 후 판단 |
| 10 | 문서 버전 측정 불가 | 인덱스·매니페스트에 버전 필드 없음 | RAG-09 미구현, 근거 버전 추적 불가 | 매니페스트에 버전 추가 |
| 11 | 복합 요청은 `COMPOSITE_NOT_SUPPORTED`로 종료 | FastAPI가 2건 이상이면 시작하지 않음 | 명세 FLOW-01, CHAT-16의 순차 처리와 차이 | 팀원 1과 범위 확인 |
| 12 | 의도 분류에 프롬프트 버전 없음 | `PROMPT_VERSION` 상수 없음 | 결과 재현·이력 추적 어려움 | 버전 추가 |
| 13 | 매니페스트 불일치 | `C02-01`, `C01-03`의 원본 파일명에 `unconfirmed`가 있으나 `verified=True`, `OFFICIAL_SHINHAN`. 전 문서 `retrieval_enabled_prod=False` | 검수 상태 근거 불명확, 운영 모드 미사용 | 검수 기록 확인 |
| 14 | 고객 안내 초안이 자동 대조가 없는데 있는 것처럼 표현 (규칙이 13건 표시, 읽어 본 8건 중 7건 해당) | 프롬프트 5번이 "일치 항목은 자동 확인 결과임을 밝히고"라고 지시. 예: "일부는 자동 확인되었고" | 고객에게 사실과 다른 안내 가능. 직원이 고치기 전에는 발송되지 않음 | matched가 비면 해당 문구 금지 |
| 15 | 불참 상속인이 없는 Case에 위임서류 확인 항목 생성 (규칙이 11건 표시, 읽어 본 6건 중 4건 해당) | `staffChecks`에 제한이 없고 `people` 값 대조 후처리가 없음 | 직원 체크리스트에 불필요한 항목 | absentCount가 0이면 위임 관련 줄 제거 |
| 16 | 모순된 근거를 한쪽으로 답함 (CON-1), 언급 안 함 (CON-2) | 모순 감지 없음, `sufficient` 판단에 의존 | 어느 쪽이 현행인지 직원이 알 수 없음 | 문서 버전(10번) 도입, 숫자 충돌 시 `INSUFFICIENT` |
| 17 | 보완 필요 서류를 고객 초안에 명시 못 함 (SUPPLEMENT 1/4 충족) | 프롬프트가 "보완이 필요할 수 있다"까지만 요구. 사유는 입력에 없음 | 화면에서는 2026-11-08 수정으로 서류·사유를 채움 | 현재 화면 동작 유지 |
| 18 | 직원 확인 항목이 평균 7.3개, 최대 10개이고 영어 서류명이 8개 Case, 25줄 | 스키마 6개에 필수 항목을 덧붙이는 구조, 3번 문제와 동일 | 중복 항목으로 체크리스트가 길어짐 | 중복 제거, 한글 표시명 전달 |
| 19 | 1차 실제 실행 51회 전부 401 | Windows 사용자 환경변수 `OPENAI_API_KEY`가 `.env`보다 우선 (`load_dotenv` 비덮어쓰기). 평가 스크립트는 수정함 | 배포 환경에서 같은 변수가 잡히면 전부 fallback | 배포 시 키 출처 고정, 무효 키 정리 |

## 채점 한계

- 자동 채점은 문구 기반이라 사람의 검토가 필요하다. 예: 규칙 하한선의 8줄은 "서류 2건"처럼 코드가 올바르게 계산한 값이 입력 원문에 없어 표시된 오탐이다.
- "Top 3 중 정답 외 문서 비율"은 같은 내용이 여러 문서에 있어도 정답 목록 밖이면 포함한다. 무관한 문서 비율의 상한으로 읽어야 한다.
- 정답셋은 한 사람이 작성했다. 팀원 교차 검토 전까지는 내부 기준이다.

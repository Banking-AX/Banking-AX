## B. 실험 환경과 조건

- 실행 시각: 2026-11-08, Windows PowerShell, Python 가상환경 `ai-server/.venv`.
- 실행 명령: `ai-server/.venv/Scripts/python.exe scripts/benchmark/c02_precheck_benchmark.py`.
- 회귀 검증: `ai-server/.venv/Scripts/python.exe -m pytest -q ai-server/tests/test_c02_integration.py ai-server/tests/test_case_brief.py ai-server/tests/test_staff_phase0.py -p no:cacheprovider` → 33 passed.
- 결과 원본: `docs/benchmark/results/c02_offline_benchmark.json` (실행마다 재생성).
- 호출 금지 준수: 공유 DB, 기존 18081/9001/5175 서버, 기존 Case, 실제 OCR, 실제 LLM을 호출하거나 변경하지 않았다.
- 실제 LLM은 `OPENAI_API_KEY` 존재 여부와 무관하게 미호출했다. `BANKING_AX_ENABLE_REAL_LLM`이 설정되지 않았고, 호출 횟수·비용 상한 승인도 없었다.

## C. 수치가 의미하는 범위 및 한계

1. 30건의 0 오탐/0 미탐은 `c02_staff_precheck`의 **현재 정형 메타데이터 분기**가 이 합성 표본의 기대 범주와 일치했다는 뜻이다. 실제 OCR 인식률, 문서 원본의 진위, 상속권·지급 적격성 또는 직원의 최종 판정을 뜻하지 않는다.
2. `OCR_MISMATCH`와 `UNREADABLE`은 Spring에서 이미 기록된 `VALIDATION_FAILED`/`NEEDS_SUPPLEMENT` 상태를 받은 경우다. OCR 공급자 호출 품질은 이 실험 범위 밖이다.
3. Fake LLM 지연은 네트워크·모델 추론·큐 대기·비용을 포함하지 않는다. 실제 LLM p50/p95로 인용하면 안 된다.
4. 안전성 결과는 결과서의 후처리 필터와 실패 fallback의 코드 경로를 증명한다. 프롬프트 우회에 대한 포괄적 보안 평가가 아니다.

## D. 최종보고서 삽입용 문장

> 상속예금(C-02) 사전점검의 합성 시나리오 30건에서, 정의한 서류 누락·판독 보완·방문 확인 신호 24건을 모두 탐지했고 오탐·미탐은 각각 0건이었다. 이 지표는 사전 정의된 메타데이터 규칙의 재현성 지표이며, 문서 진위나 상속권의 자동 판정 정확도를 의미하지 않는다.

> 직원 Agent는 구조화 출력 검증과 안전 필터를 거치며, 위험한 확인·승인 표현을 포함한 합성 응답은 최종 결과서에서 제거되었다. LLM 호출 실패 주입 시에는 `RULE_FALLBACK`으로 전환되어 직원 확인 경로를 유지했다.

> 오프라인 단위 경로에서 C-02 정형 사전점검의 p50/p95는 0.004/0.006 ms, Fake LLM 결과서 경로는 3.823/5.860 ms였다. 두 값은 외부 OCR·DB·HTTP·실제 LLM 지연을 제외한 코드 경로 측정값이다.

## E. 수행하지 못한 실험

1. 실제 LLM 호출 성능/비용: 명시적 활성화 환경변수, 호출 횟수·비용 상한 승인이 없어 미수행.
2. 격리 DB와 별도 Spring 서버의 20건 동시 예약: `T2_VERIFY_DB_URL`, DB 계정, 격리 서버가 설정되지 않았고 Docker API 접근도 거부되어 미수행. 기존 서버/공유 DB는 사용하지 않았다.
3. k6 API p50/p95·처리량·오류율: 위 격리 서버 부재로 미수행. 재현 스크립트 `scripts/benchmark/reservation_20vus.js`는 `ISOLATED_RUN=1` 및 기존 포트 차단을 강제하며, 409 업무 충돌은 서버 오류(5xx)와 분리한다.

## 결과 해석

1. **직원 검토가 실제로 개선되는가:** 판단 불가. 사람 실험을 하지 않았다.
2. **새로운 금융업무 위험을 만드는가:** 상태 무단 변경과 미승인 적용은 재현되지 않았다. 다만 모순 근거 단정(`case-brief-5`), 자동 대조 과장은 실제 모델에서 관측됐고 수정본은 재측정 전이다.
3. **잘못된 LLM 결과가 직원 승인 전에 차단되는가:** 정해진 표현과 숫자, 근거 문서는 차단된다. 표현을 바꾼 주장까지 막는 것은 아니며, 최종 차단은 직원 검토다.
4. **변경 후 과거 정보를 재사용하지 않는가:** 승인 안내는 버전별로 관리된다. 검토 의견은 수동 재생성해야 갱신되고, 이력은 남지 않는다.
5. **모델·RAG 실패 시 통제가 유지되는가:** 유지됐다.
6. **금융기관 도입 요구 충족:** 직원 승인 통제, 이벤트 감사, 권한 분리(Spring)는 구현됐다. FastAPI 인증, 의견 이력·버전 추적, 실제 RAG 버전 관리, 업무시간 검증은 미충족이다.

## 최종보고서에 쓸 수 있는 문장

> 교육용 가상 업무기준과 합성 Case로 변경정보 수신부터 직원 승인까지 실제 API 경로를 검증했다(검사 67개). Spring의 영향 Case 식별은 합성 66건에서 정답과 일치했고, 미승인 기준이 직원 Agent 입력에 포함된 사례와 Agent가 Case 상태를 변경한 사례는 없었다. LLM 장애 시 규칙 기반 대체와 상태 보존도 확인했다.

> 다만 승인된 변경의 구체 확인항목이 검토 의견에 전달되지 않는 공백, 충돌 감지의 제한된 범위, FastAPI 일부 경로의 인증 부재를 확인했다. 인증 문제는 배포 전 차단 항목이다. 직원 업무시간 절감 효과는 사람 대상 실험을 수행하지 않아 측정하지 못했다.

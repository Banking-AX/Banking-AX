# 직원 Agent 사용 전후 비교 실험 설계

**상태: NOT_RUN.** 실제 사람이 수행하지 않았으므로 업무시간 절감 수치는 없다.

## 가설

업무기준 변경으로 영향을 받는 C-02 Case에서, Agent를 쓰면 필수 확인사항을 더 빠르고 정확하게 파악하면서 잘못된 안내가 늘지 않는다.

## 조건

| | A: Agent 미사용 | B: Agent 사용 |
|---|---|---|
| 접수 정보, OCR 대조, 서류 원본 | 제공 | 제공 |
| 업무기준 문서, 변경 안내, 변경 전후 원문 | 제공 | 제공 |
| 변경 영향 분석, 검토 의견, 안내 초안 | 없음 | 제공 |

두 조건의 원본 자료와 완료 기준은 같다. A 조건의 자료 접근을 어렵게 만들지 않는다.

## 절차

- **평가자:** 팀원 5명까지. 실제 은행 직원이 아니므로 숙련도 일반화 불가.
- **Case:** 난이도가 같은 세트 2개, 세트당 4건 (영향 있음 2, 영향 없음 1, 미승인 또는 상충 1). 정답은 실험 전에 고정.
- **교차 배정:** 평가자마다 세트 1을 A, 세트 2를 B로 하거나 반대로 한다. 수행 순서도 절반씩 뒤집는다. 같은 Case를 두 조건으로 반복하지 않는다.
- **연습:** 본 실험과 다른 Case 1건으로 화면에 익숙해진다. 측정에서 제외한다.

## 측정 정의

**시작:** Case 자료를 연 시점. **완료:** 필수 확인사항 목록과 고객 안내문을 작성·검토하고 제출한 시점. 버튼 클릭만으로 완료로 보지 않는다.

| 항목 | 정의 |
|---|---|
| 완료시간 | 건당 초, 평가자별 기록 |
| 필수 확인사항 누락 | 정답 목록 대비 누락 건수 |
| 잘못된 기준 적용 | 미승인·구버전 기준 사용 건수 |
| 불필요한 서류 요구 | Case 조건에 없는 서류 요구 건수 |
| 잘못된 확정 안내 | 승인·지급·기한을 단정한 건수 |
| 안내문 수정 횟수 | B는 초안 대비 수정, A는 초안 작성 후 수정 |
| 근거 확인 가능 여부 | 문서·버전을 제시했는지 |

## 채점

- 사용 조건이 지워진 결과물을 참여하지 않은 사람이 채점한다. 불가능하면 그 한계를 명시한다.
- 평균과 중앙값을 함께 보고한다. 평가자가 5명 이하면 통계적 유의성을 주장하지 않는다.
- Agent가 더 느리거나 부정확한 사례도 그대로 기록한다.

## 실행 전 필요

1. 배포 차단 항목과 검토 의견 공백(변경 상세 미전달)에 대한 수정 여부 결정. 공백을 그대로 측정하면 Agent의 현재 한계가 결과에 반영된다.
2. B 조건에 필요한 실제 LLM 출력을 미리 생성한다 (Case 8건 × 의견 1회 + 영향 분석 1회, 별도 승인).
3. 평가자 일정 약 1.5시간.

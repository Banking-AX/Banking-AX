- A 업무 이메일 0건 정책(T-12)은 이메일 기능 자체가 없어 자동 충족.

| 단계 | 구현 | 화면 |
| --- | --- | --- |

| 고객 상세 | 상태 배지(AI 점검 / 직원 검토 / 결과), 결과 카드, 예약 카드, 타임라인, 방문 계획, 서류 현황 | `/tasks/c02/cases/:caseId` |

**빠진 것**
- 인증번호 단계에서 제출 불가(팀원 1 PR 대기). 제출 이후 화면은 단위 테스트로만 확인.
- **접수 취소 API 없음**(T-02/T-03 미구현). 상세 화면에는 "미연결" 안내만 표시.
- 사전점검 중 고객 추가 확인(`clarification`) 없음 — Flyway에 테이블 자체가 없음.
- 위임장 접수번호(`DELEGATION_RECEIPT_NO`)가 파일 업로드 슬롯으로 처리되는 설계 문제.
- 접수번호(C-날짜-번호)는 DB 컬럼이 없어 화면에서 만든 표시용 값.

### 2-4. 직원 Agent 사전점검 (공통 엔진 + C-02 점검)

- **구조**: LangGraph 3노드 `load_case → execute_check → attach_rag`. 노드 실패 시 `FAILED_NEEDS_STAFF`로 넘기고, Case·예약·알림을 쓰는 노드는 없음(설계 의도대로). `ai-server/app/core/staff_engine/graph.py`
- **C-02 점검 내용**(`tasks/c02/checks.py`): 전부 **정해진 규칙 항목**이다.
  - 필수 입력 누락
  - 범위 밖 조건
  - 서류 미제출·보완 필요
  - 잠정 불참 상속인 직원 확인
  - 일반 증명서 OCR 미적용 안내
- **빠진 것**
  - LLM 의미 분석(불일치 후보 분석) 없음 — 명세 08~09장의 "의미적 불일치 후보 분석" 미구현.
  - Spring이 점검 요청에 `ragQuery`를 보내지 않아 **업무 근거(RAG)가 결과서에 붙지 않음**.
  - OCR 추출값을 점검에 사용하지 않음.
  - 결과서(STAFF-20) 형식 없음. 직원 화면에는 항목 목록만 표시.
  - Agent 측 Case 조회가 `FakeCasePort`(요청 값을 그대로 등록)라 Spring 재조회 검증이 형식적.

### 2-5. 직원 결과 확정·통지
